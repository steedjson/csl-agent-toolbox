# 动态功能图标生成提示词

你是产品图标设计师兼前端工程师。请读取我提供的产品代码，为它生成一套风格统一、悬停时会形变的功能图标（SVG + JS）。按下面的步骤和规范执行，每一条都是硬性要求。

## 0. 输入

- 产品代码仓库，或一份功能清单。
- 一个参照图标：产品里已有、最能代表品牌气质的图标（例如文件夹）。没有的话，使用下文的默认参数。
- 如果同时拿到了 kubai-icons 仓库（或同等的实现），必须直接复用 `src/engine.js`：颜色推导、外描边遮罩、厚度带渐变、投影和内发光滤镜、插值动画、色板都已经实现好了。新图标只按 `src/icons.js` 里已有图标的写法追加，再把名字加进 `src/app.js` 的 `ORDER`。不要重写引擎，也不要另起一套写法。动手前，先读几个结构最接近的现成图标当范例（例如文件夹、信封、下载、日历）。

## 1. 先读代码，再定清单

1. 从代码里找出用户看得到的功能：路由、设置项、菜单、按钮文案、多语言词条。挑出最常用、最能代表产品的 N 个。
2. 每个功能写一句"物体隐喻 + 悬停动作"（只交付静态 SVG 时，确定物体即可，悬停动作可以省略）。物体要是现实里一眼认得的东西（文件夹、信封、日历、锁、时钟）。动作必须是这个物体本身会做的事：文件夹打开、信封拆开、日历翻到下一天、锁打开、时钟往前走、齿轮转动。不要用引申义，比如为了表达"历史"让时钟倒转。
3. 从参照图标里提取构造：分几层、每层的颜色、描边的宽度和位置、圆角、高光和投影参数、动效时长和曲线。下文的默认值取自 Lumno 的文件夹图标；参照不同时，以提取结果为准。

## 2. 画布与网格

- viewBox 为 `0 -2 31 29`，中心 (15.5, 12.5)。所有图标按中心对齐，不按底边对齐。
- 四种 keyline（指填充尺寸，描边另加）：圆形直径 23；正方形 20.6；横向 23×18.4；纵向 18.4×23。即 Material 的 20 / 18 / 20×16 网格乘以 1.15，横向宽度与参照图标的主体同宽。
- 每个图标先归到一种 keyline。云、齿轮齿尖这类有机形状视觉上偏小，可以超出 keyline 最多约 1 个单位来补偿。
- 组合图形（页面加放大镜、门加箭头）整体落在 keyline 内，并分清主次：主体是物体本身；放大镜、角标、方向箭头这类辅助元素要明显更小，压在主体的一角或紧挨在旁边。
- 辅助元素可以压在主体的一角（放大镜压在页面角上），也可以紧挨在主体旁边；紧挨时和主体留 1–1.5 个单位的空隙。第 4 节"要么贴住、要么离开 2 以上"针对的是会移动的部件，不适用于静止的辅助元素，不要为了它把箭头推远。
- 组合图形里，主体自己至少要有一个方向顶满所选 keyline（例如门要和其他纵向图标一样高），辅助元素放在剩下的空间里，整体外框不超过 23×23。不要为了塞下辅助元素把主体缩小，否则在 24px 下会比其他图标轻一截。

## 3. 分层：层次感的来源

每个图标至少两层，参照文件夹。后片加前片算两层；后片加面积足够大的白色内容（表盘、屏幕、格子、白页）也算两层：

- 后片：中间调渐变加投影，构成主体轮廓。
- 内容（可选）：纯白，不加描边，相当于文件夹里那张纸。
- 前片：浅色渐变加顶部内发光，压在后片前面。前片的上角要有自己的圆角（1.6–2），让后片在角上露出来，前后遮挡才读得出来。前片不能和后片轮廓完全重合、顶边一刀直切，否则看起来像一条分割线。
- 例外：顶部的条带（日历头、窗口标题栏）可以和主体共用上角轮廓、底边一刀直切，因为它表示的是物体本身的分区，不是压在前面的另一片。这种条带要用浅一档的前片颜色并带内发光，和主体明显区分开。
- 闭合状态必须真的闭合。例如信封盖的下边要与口袋的 V 完全重合，盖子的上角要与主体的圆角一致。
- 内容一旦移出容器、落到白色或浅色背景上（例如从垃圾桶上方露出的卡片、从钱包里抽出的卡、打印机吐出的纸），就不能再用纯白：改用前片的浅色渐变，再加描边，否则边缘会消失在背景里。伸出主体的小附件（日历的铁圈、剪贴板的夹子）可以保持白色，但必须带描边；绝不能出现既没有颜色、又没有描边的纯白形状落在浅色背景上。
- 每个状态和动画的每一帧都要检查 Z 轴关系：被盖住的部件，它的描边不能从前面部件的边缘露出来。翻开的部件以铰链为轴；铰链要放在主体侧边已经变直的位置，铰链处用直角，让主体的侧边描边直接接上翻开部件的侧边描边，主体被盖住的那段（包括圆角）整段藏在后面。

## 4. 圆角、描边、色带

- 主体填充圆角 2.2，内容圆角 1.2。
- 描边宽 1，放在外侧（相当于 Figma 的 Outside）。代码实现：描边画成 2 宽，再用自身形状做 mask 遮掉内侧一半。这样填充不会被挤小，看到的圆角是 2.2 + 1 = 3.2，与参照一致。
- 相接的两条边要互相重叠（例如垃圾桶盖压住桶口），不能让两条描边并排、变成一条粗线。
- 描边内侧如果留一圈色带（相框、表盘外圈），色带至少 2 个单位；不够就去掉色带，让内容直接贴到边。绝不能出现"描边里面只剩一条细缝"。
- 会移动的部件（扫描条、翻开的封面）同样要遵守：静止和悬停结束两个状态里，它和别的元素之间要么正好贴住，要么离开 2 个单位以上。"正好贴住"指两者的外缘距离为 0、描边互相盖住、看起来只有一条线；0 到 2 之间的缝都不行。动画途中短暂经过可以接受，但不能停在那里。
- 底部厚度带（高 1.2，是渐变里一个硬切的深色台阶）只加在平底矩形上，而且要求底部是空的：最下面的元素离底边至少约 3 个单位，这一片本身也不能太矮（低于约 8 个单位就不加）。底部有元素（格子、门、钥匙孔、压在底部的放大镜）或空间很窄时就不加。圆形、云、齿轮等曲面一律用平滑渐变。

## 5. 光影

- 投影：y 偏移 2，模糊 2，不透明度 21%，颜色由主色推导（参考色 #8AB6FF，按第 6 节同样推导）。
- 顶部内发光：内阴影 y 偏移 0.7，模糊 0.35，纯白，混合模式 overlay，不透明度 50%。用 100% 会把浅色直接推成纯白。加在主要的彩色形状上（后片和前片都可以加），不要加在白色内容旁边，否则会出现一圈奇怪的光。
- 会旋转的部件（齿轮）要把投影和内发光放在旋转的外层，光永远从上方来。

## 6. 颜色

- 每个图标只有一个主色。所有渐变色标、描边、投影，都从参考蓝 #5393FF 的相对明暗推导到主色：
  - amt = (源色 − 参考色) ÷ (255 − 参考色)，逐通道计算；蓝通道沿用红通道的 amt。
  - amt ≥ 0 时，结果 = 主色 + (255 − 主色) × amt；否则，结果 = 主色 × (1 + amt)。
- 参考色标：
  - 后片 #93BBFF → #81B0FF；带厚度带时，末端为 #4389FF → #97BEFF。
  - 前片 #CCDFFF → #B2CEFF；带厚度带时，末端为 #89B5FF → #97BEFF。
  - 描边 #5393FF；深色标记 #2F6FE0 或 #4389FF；浅一档的标记 #89B5FF（需要和深色标记分出上下层时用，例如下层的时针、指南针的南半）；浅线 #D3E2FC。
- 提供以下色板，并支持切换：彩色（每个图标一个主色）；蓝灰（清透做法：取一个偏蓝的灰作基色，例如 #6F87B5，填充用基色混入约 10% 白色，描边和深色标记用基色再压暗约 16%，原本压在中间调上的白色标记改成深色，面积较大的纯色填充改成从上到下的白→纯色渐变）；黑色（统一 #2E3036）。换一个基色，就能把同样的清透做法迁移到其他颜色，例如青瓷 #5BA3A8、薄荷 #5FAE8A、薰衣草 #8C83C6、杏色 #C9946A。切换时颜色本身也要走动画。

## 7. 标记：图标里的线、箭头、符号

- 先分清两种白：
  - 白色内容：代表实物材质的面，例如纸、屏幕、门洞、按键、表盘、格子。永远是纯白 `fill="#fff"`，在任何色板下都不变。
  - 白色标记：画在彩色主体上的符号、文字线、箭头、图案，例如二维码的定位图形、播放三角、问号。写成 `data-w`，清透色板下会自动改成深色。
- 标记用白色还是深色：在中间调的后片上用白色标记；在浅色前片或白色内容上用深色（例如按键上的运算符是画在白色按键上的标记，用深色）；叠在主体上的辅助物（放大镜）用深色，才能和主体分开。
- 线宽只用三档：内容线 1.6、方向性符号（箭头等）2.2、描边 1。不要更粗。唯一的例外是需要上下层粗细对比的指针类部件：下层 2.6，上层 2.0（参照时钟）。
- 细节要少：一块内容最多两条线；除非是语义核心（日历上的日期），不要放文字。
- 任何标记或细节的最小尺寸是 2.4 个单位（24px 下约 1.9px）。比这还小的小圆点、小刻度、小符号要么去掉，要么放大到 2.4 以上；语义核心（二维码的定位块、计算器上的运算符）也不例外。
- 核心元素要足够大，在 24px 下仍然是图标里最大的东西。
- 有粗细的笔画不能互相叠压：箭头的头部用一个实心三角形，盖住线段的末端，不要用几条粗描边拼成，否则尖端会糊成一团。两个笔画之间（例如一支箭头的头和另一支的尾）要留出清楚的空隙。
- 会重叠的部件要分层上色：例如时针在下，用浅一档的颜色；分针在上，用深色；中心轴盖在最上层。不要把颜色相近的部件叠在一起。

## 8. 动效

- 每个部件只写两组关键帧：静止和悬停。时长 460ms，曲线 cubic-bezier(0.22, 1, 0.36, 1)，逐个数字插值。路径保持相同的命令结构，才能逐数插值。
- 动画永远从屏幕上当前的形状出发。进出再快也能中途折返，不跳帧。
- 翻转、翻页用围绕铰链的缩放：正面朝下时在前，越过铰链后换成背面并移到内容后面。不要用淡入淡出，否则只会看到一片模糊。
- 有先后顺序的动作，用一个进度参数派生（信封：先开盖，再抽信）。
- 悬停时元素之间不要产生新的遮挡。需要"落入"或"升起"时，留出空隙，让符号始终完整可见。如果经过本身就是动作（扫描条扫过二维码），途中可以经过，但静止和悬停结束两个状态都不能遮挡。
- 持续或往复的动作（闹钟一直响、指南针来回摆）也只用两组关键帧：用一个 0→1 的进度参数，在 `draw` 里派生出一段先振荡、再收敛停住的运动。结束状态必须稳定，不要做无限循环。
  - 静止和结束都要摆正的（闹钟、扫描条）：角度 = A·(1−o)·sin(kπo)，k 取整数，o=0 和 o=1 时都为 0。
  - 从偏离的位置收敛到目标的（指南针从偏 40° 摆回正北）：角度 = A·(1−o)·cos(kπo)，o=0 时就是起始偏角。
  - 曲线本身是强 ease-out，振荡会挤在前段，k 取 2–3 就够。鼠标移开时动作会倒着再播一遍，这是两组关键帧的固有行为，可以接受。
- 动作必须表达物体本身的语义（见第 1 节）。
- 只交付静态 SVG 时，本节可以跳过：`target` 的静止和悬停返回同一组数值即可。分层、描边、光影、颜色、标记的规则照常适用。

## 9. 交付格式

每个图标交付三部分：

- `svg(u)`：返回图标的 SVG 片段。
  - 渐变和滤镜：`u.lo(h)` / `u.up(h)` 是带厚度带的后片和前片渐变，只用于满足第 4 节条件的平底矩形，h 是它的高度；`u.loS` / `u.upS` 是平滑渐变；`u.sh` 是投影，`u.hi` 是顶部内发光；`u.pure('#5393FF')` 用于面积较大的纯色填充（清透色板下会变成白→纯色渐变）；`u.id('名字')` 生成本图标内唯一的 id（clipPath 等用）。
  - 需要描边的路径加 `class="ol"`（常量 `OL`）。内容线用 `LINE`（浅线）或 `ACC`（主色线）；深色标记用 `DEEP`（填充）或 `DEEPS`（描边）。其他需要随主色变化的颜色写成 `data-t="属性:参考色"`。
  - 压在中间调后片上的白色标记写成 `fill="#fff" data-w="fill"` 或 `stroke="#fff" data-w="stroke"`，清透色板下会自动改成深色。白色内容（纸、格子、信纸）直接写 `fill="#fff"`。
  - 会旋转、翻转、缩放的部件：投影和内发光放在变换的外层，描边单独放在另一个同样变换的组里（参照齿轮、星标）。
  - 描边遮罩和它的路径在同一个坐标系里，放进同一个变换组会自动跟着变换。时钟类图标可以直接用常量 `CLOCK_MINUTES`（10:08，在任何尺寸下都认得出是钟）。
  - 可用的几何工具：`rr(x, y, w, h, r)` 圆角矩形，`rp(points, r, full)` 圆角多边形，`R(x, y, w, h)` 矩形顶点，`circ(cx, cy, r)` 圆，`lines(x, y, widths)` 间距 3 的内容线，`star`、`gear`、`cloud`、`frontPiece`（从圆形或云形下部切出前片）、`sector`；常量 `KR = 2.2`（主体圆角）、`CR = 1.2`（内容圆角）。
  - 绕向：`circ` 是逆时针，`R` 给出的顶点（因此 `rr`、`rp(R(...))`）是顺时针。默认的 nonzero 规则下，同一条路径里两个绕向相反的形状重叠，重叠处会被挖空：想挖孔（例如指环的中心）正好利用这一点；想把它们合成一个实心形状，就要让绕向一致，或者拆成两条路径。
- `target(hover, state)`：返回静止或悬停时的数值参数（坐标、角度、缩放、进度）。参数名不能用 `c` 或 `e`，它们分别留给填充色和描边色。需要点击切换的状态（如书签收藏）加 `tap: true`，状态从 `state` 读。
- `draw(p, E)`：用插值后的参数写回路径和 transform。`E` 是所有带 `data-n` 的元素。

静态交付时，图标照样按上面三部分写进 `src/icons.js`（引擎负责画），再用 `scripts/export.mjs` 导出成独立的 SVG 文件：颜色按所选色板解算好，描边宽度等样式写进元素属性，id 带上每个图标自己的前缀，不依赖脚本和样式表。

## 10. 自检清单：每一轮都做

有 `scripts/check.mjs` 时直接用它：它会按下面第 2、5、6 条的要求截出静止、悬停、悬停过程的中间帧（`frames.png`，0%–100% 共 6 行）、24px、28px 和所有色板，并读出每一页的脚本报错。用 `--only` 指定新图标，用 `--with` 加几个现有图标一起对比，用 `--scale 3` 放大检查细缝，用 `--accent #F59E0B` 把所有图标换成同一个浅主色来做第 3 条检查。往复类动作的结束帧和静止一样，只能从 `frames.png` 判断。

1. 在 24px 和 28px 下渲染：每个图标都能一眼认出，视觉大小一致。
2. 静止、悬停结束、悬停过程中各截一张图（只交付静态时只看静止）。
3. 所有色板都看一遍，重点检查清透色板和浅主色（黄色等）上的标记是否还看得清。
4. 逐条检查：
   - 有没有细缝色带。
   - 有没有并排变粗的描边。
   - 内容有没有描边。
   - 前后片是否用圆角错开。
   - 闭合状态是否真的闭合。
   - 悬停时有没有产生遮挡。
   - 动作是否符合物体本身的语义。
5. 在绘制代码之前就注册错误监听，页面加载期的脚本错误也要捕获，不要只看画面。用本地文件打开时，外部脚本的报错只会显示 "Script error."，这时把脚本内联进测试页再看完整报错。无头模式下，把错误写进页面（例如根元素的 `data-err` 属性），再用 `--dump-dom` 读出来。
6. 截图检查时开启"减少动态效果"（例如 Chrome 的 `--force-prefers-reduced-motion`），让状态直接跳到终点。否则无头浏览器里动画常常停在半路，截到的是错误的中间状态。
7. 新图标要和现有图标放在一起、同样大小截图对比：视觉大小、线条粗细、层次和颜色都要和现有的一致。
8. 增删图标后，同步更新 README 里提到的数量，以及展示页的列数：每个断点的列数都要能整除图标总数，不留半排。断点可以增、删、改，只要满足这一条。
